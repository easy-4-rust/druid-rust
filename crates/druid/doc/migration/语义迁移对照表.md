### 3.1 CallableStatement 当前重载账本

| Java 签名族 | Rust API/对象 | 输入/输出与副作用 | 证据 | 状态 |
| :--- | :--- | :--- | :--- | :--- |
| `registerOutParameter(int/String, int[, int/String])` 六重载 | 六个 `register_*_out_parameter*` | index/name、sqlType、scale/typeName 原样进入物理 SPI；错误使缓存条目失效 | Java 69 个 Callable 测试 + Rust callable contract | `BEHAVIOR_VERIFIED`（测试驱动） |
| `setNull(String,int[,String])` 两重载 | `set_named_null*` + `CallableInputParameter::Null` | 保留 `sqlType/typeName`，不再压缩成无类型 `Value::Null` | Rust descriptor 精确断言 | `IMPLEMENTED_UNVERIFIED` |
| `setObject(String,Object[,int[,int]])` 三重载 | `set_named_object*` + `CallableInputParameter::Object` | 保留 `targetSqlType/scale` | Rust descriptor 精确断言 | `IMPLEMENTED_UNVERIFIED` |
| `setBoolean/Byte/Short/Int/Long/Float/Double/String/NString/Bytes` | 同语义 `set_named_*` | 每个 Java setter 使用独立 enum variant，驱动可区分调用 | Rust callable contract | `IMPLEMENTED_UNVERIFIED` |
| `getString/Boolean/Byte/Short/Int/Long/Float/Double/Bytes` index/name | 同语义 `get_*` / `get_named_*` | 池化层统一错误与缓存淘汰，类型转换由 `PhysicalCallableStatement` 方法承担 | Rust callable contract | `IMPLEMENTED_UNVERIFIED` |
| `setBigDecimal(String,BigDecimal)`、`getBigDecimal(int[,scale]/String)` | `set_named_big_decimal`、`get_*_big_decimal*` | `bigdecimal::BigDecimal` 保留任意精度和 scale；Java null 用 `Option` 区分 | Rust core 2/2 + pool 2/2 | `IMPLEMENTED_UNVERIFIED` |
| `set/get Date/Time/Timestamp(int/String[,Calendar])` | 同名 snake_case API + `CallableCalendarArgument` | `chrono` 强类型；区分无 Calendar 重载、显式 null Calendar、实际时区标识 | Java 69 个 Callable 测试 + Rust Calendar 调用账本 | `IMPLEMENTED_UNVERIFIED` |
| `getBlob(int/String)`、`setBlob(String,Blob/InputStream[,long])` | `get*_blob` / `set_named_blob*` + `JdbcBlob/JdbcInputStream` | Blob 保留物理对象身份和 11 方法资源 SPI；流不预读；区分 Java null、无长度重载和显式 long | Java Callable 101/101 + Rust Blob 2/2 + pool 2/2 | `IMPLEMENTED_UNVERIFIED`（无 Callable E7） |
| `getClob(int/String)`、`setClob(String,Clob/Reader[,long])` | `get*_clob` / `set_named_clob*` + `JdbcClob/JdbcReader` | Clob 保留对象身份和 13 方法资源 SPI；Reader 不预读；区分对象 null、Reader null、无长度和显式 long | Java Callable 101/101 + Rust Clob 2/2 + pool 2/2 | `IMPLEMENTED_UNVERIFIED`（无 Callable E7） |
| `getNClob(int/String)`、`setNClob(String,NClob/Reader[,long])` | `get*_n_clob` / `set_named_n_clob*` + `JdbcNClob/JdbcReader` | 保留 national-character 类型身份、Java null 与 Reader/long 重载 | 同上 | `IMPLEMENTED_UNVERIFIED`（无 Callable E7） |
| `getCharacterStream/getNCharacterStream(int/String)` | `get_*_character_stream` / `get_named_*` | 返回共享身份的 `JdbcReader`，不转成 String；SQL NULL 为 `None`，类型错误进入异常淘汰 | Rust pool index/name/null/type-error | `IMPLEMENTED_UNVERIFIED` |
| `setCharacterStream(String,Reader[,int/long])`、`setNCharacterStream(String,Reader[,long])` | `set_named_*_character_stream*` + `JdbcCharacterLength` | `Unspecified/Int/Long` 三种 descriptor 保留 Java 精确重载；负长度不在池化层改写；Reader 不预读 | Rust descriptor/错误/关闭契约 | `IMPLEMENTED_UNVERIFIED` |
| `getObject(int/String)` 标量部分 | `CallableOutputValue` | 保留 Decimal/Date/Time/Timestamp 类型身份；ResultSet/LOB 等不得伪装成标量 | Rust typed OUT contract | `PARTIAL` |
| URL、Array/Ref、RowId、SQLXML、二进制流、map/typed `getObject`、ResultSet 包装、unwrap | 已有同语义 API/资源对象 | 不得用 String/Bytes 静默替代；真实 driver 必须逐类型验证 | 115 个 Java 方法入口账本；真实存储过程证据待补 | `IMPLEMENTED_UNVERIFIED/PARTIAL` |

上述测试驱动证据不是支持存储过程数据库的 E7 证据，因此整个对象仍为 `PARTIAL`。

## 6. SQLite 真实证据

`crates/druid/tests/sqlite_core_semantics_test.rs` 纵向穿过
`druid facade → DruidPool → DruidPooledConnection → statement cache →
ToastyConnectionAdapter → Toasty Driver → SQLite`，验证：

- 真实 DDL/DML/查询与参数绑定；
- PreparedStatement 真实执行和连接级缓存命中；
- 事务 rollback；
- close 后同一物理连接复用和计数；
- `COUNT(*)` 按 SQLite 运行时 INTEGER 类型解码；
- CallableStatement 明确 `UnsupportedOperation`。

SQLite 不支持存储过程、XA 和 vendor SQLState，相关语义不得标 `PASS`。

当前过渡测试
`crates/druid/tests/toasty_connection_adapter_test.rs` 还直接验证 factory
metadata、六类 `Value` 参数、`last_insert_rowid()`、prepared close、完整保存点、
SQLite 只支持 Serializable、只读明确 unsupported、discard 和未知 URL scheme。
归并后该合同必须迁到 `crates/druid/tests` 或 `crates/druid/src/toasty` 的模块测试，
且由 `druid` 默认构建执行。
