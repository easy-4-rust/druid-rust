## 一、总目标

以 Alibaba Druid 1.2.8 为蓝本，实现功能语义对齐的 druid-rust workspace，
目标覆盖 Druid 的连接池、Filter 链、SQL 防火墙、统计、动态数据源与监控面。

### 迁移原则

1. **功能语义对齐，实现方式 Rust 化**：Java 反射 → trait 对象；JDBC Proxy → 装饰器；JMX MBean → tracing/metrics；Spring Boot autoconfigure → Builder pattern
2. **SQL 解析不移植**：Druid 自研 SQL parser（1268 个 Java 文件、29 个方言）替换为 `sqlparser-rs`（1 个 crate），Wall 和 Stat 走 sqlparser AST
3. **每个 .rs 文件只对应一个 Java 对象**：对齐 vernal-expression 的一文件一对象规范
4. **所有公开类型必须有中文文档注释**：结构体、枚举、trait、方法、字段
5. **模块路径 snake_case**，类型 PascalCase，方法 snake_case
6. **连接池不自研**：复用 `druid-pool`（trait 抽象层），底层 driver 通过适配器接入 `rbdc` / `sqlx+deadpool` / `sqlx+bb8`

## 五、SQL 解析迁移策略（ADR-002 展开）

### 为什么不动 Druid 的 SQL parser

| 维度 | Druid SQL parser | sqlparser-rs |
| :--- | :--- | :--- |
| 文件数 | 1268 | 1 |
| 方言数 | 29 | 10+（Postgres/MySQL/MSSQL/SQLite/Hive/DuckDB/ClickHouse/BigQuery/Snowflake/Redshift/Databricks） |
| AST 节点 | 72 expr + 283 statement | 完整覆盖 |

### 迁移等价关系

| Druid Java SQL | sqlparser-rs | druid-rust |
| :--- | :--- | :--- |
| `SQLStatementParser.parseStatement()` | `Parser::parse_sql()` | `SqlParser::parse()` |
| `SQLExprParser` (6502 行) | `Parser` 内部 | `druid-sql` 不暴露 |

| `WallProvider.check(sql)` | — | `Wall::check(&ParsedStmt)` |
| 方言 Lexer (28 个) | sqlparser `Dialect` trait | `SqlParser::new(driver)` |

## 六、Filter 链迁移策略

### Druid Java Filter 接口（100+ hook 方法）→ druid-rust BeforeFilter + AfterFilter

Druid Java 的 `Filter` 接口有 100+ 个 hook 方法，覆盖 JDBC 的每个操作
（`connection_connect`、`statement_execute`、`resultSet_next` 等）。

druid-rust 将其精简为 **2 个 trait**：

| Druid Java | druid-rust | 理由 |
| :--- | :--- | :--- |
| `Filter.connection_prepareStatement(chain, conn, sql)` | `BeforeFilter.before(ctx)` | SQL 拦截只需要 before/after |
| `Filter.statement_executeQuery(chain, stmt, sql)` | `AfterFilter.after(ctx, result, elapsed)` | 统计只需要 elapsed + ok |
| `Filter.resultSet_close(chain, rs)` | 不需要 | 连接归还由 Drop 处理 |
| `Filter.connection_setAutoCommit(...)` | 不需要 | 事务由 begin/commit/rollback 处理 |

### 内置 Filter 对应

| Druid Java Filter | druid-rust | 状态 |
| :--- | :--- | :--- |
| `StatFilter` | `druid_stats::StatFilter` | 🗓️ S4 |
| `WallFilter` | `druid_sql::WallFilter` | 🗓️ S3 |
| `LogFilter` / `Slf4jLogFilter` | `tracing` 集成 | 🗓️ S4 |
| `CounterFilter` | `druid_stats::CounterFilter` | 🗓️ S4 |
| `ConfigFilter` | 不迁移（密码解密由 Vault/SecretRef 处理） | 🚫 |
| `EncodingConvertFilter` | 不迁移（Rust 原生 UTF-8） | 🚫 |
| `MergeStatFilter` | 合并到 `StatFilter` | 🔀 |

## 九、覆盖率豁免记录

### 9.1 Rust 源码覆盖率工具的已知限制

在 `cargo-llvm-cov` 分析中，`connection.rs` 仍有约 52 行标记为"未覆盖"，原因是：

1. **trait 默认方法体**（lines 106-176）：`Connection` trait 的 `rollback_to`、`set_savepoint`、`set_savepoint_named`、`release_savepoint`、`abort` 等默认实现的函数体在源文件中计为"未覆盖"，因为 Rust 源码覆盖率工具将 trait 定义中的默认方法体视为"未被调用"——即使它们通过 trait dispatch 实际执行了。
