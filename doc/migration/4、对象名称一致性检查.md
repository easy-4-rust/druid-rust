## 四、业务逻辑一致性检查

### ✅ 计划完全一致的逻辑

- 连接池获取/归还（`getConnection` → `Pool::get()`）
- 连接池配置（100+ setter → `PoolConfig` struct）
- 连接验证（`ValidConnectionChecker` → `ValidConnectionChecker` trait）
- 致命异常判断（`ExceptionSorter` → `ExceptionSorter` trait）
- Filter 链执行（`FilterChain` → `FilterChain`）
- Wall SQL 检查（`WallProvider.check` → `Wall::check`）
- Wall 配置（`WallConfig` 30+ 项 → `WallConfig` struct）
- SQL 合并统计（`JdbcSqlStat` → `MergedSqlStat`）
- 慢 SQL 检测（`slowSqlMillis` → `slow_sql_threshold`）
- 数据源切换（`HighAvailableDataSource` → `DynamicDataSource`）
- 监控端点（`StatViewServlet` → axum router）
- 数据源信息 API（`/druid/datasource.json` → `/druid/api/datasources`）
- SQL 统计 API（`/druid/sql.json` → `/druid/api/sql/top`）
- Wall 统计 API（`/druid/wall.json` → `/druid/api/wall`）

### ⚠️ 部分一致的逻辑

| 逻辑 | Druid Java | druid-rust | 差异 |
| :--- | :--- | :--- | :--- |
| Filter hook | 100+ 方法 | 2 trait | 精简为 before/after |
| 连接池调度 | `DruidConnectionHolder[]` + `poolingCount` | `VecDeque` + `Mutex` | 实现不同 |
| 驱逐线程 | `DestroyConnectionThread` | tokio task | 实现不同 |
| 创建线程 | `CreateConnectionThread` | tokio task | 实现不同 |
| 泄漏检测 | `removeAbandoned` 遍历 | `LeakDetector` 计时器 | 实现不同 |
| SQL 解析 | 自研 1268 文件 parser | `sqlparser-rs` 1 crate | 完全替换 |
| 监控框架 | JMX MBean | metrics + tracing | 完全替换 |
| 配置加载 | `configFromProperties` | Builder pattern | 完全替换 |
| 动态数据源 | ZooKeeper + HA | ArcSwap + DashMap | 完全替换 |
| 多方言 Wall | 7 个 WallProvider | 1 个 Wall + dialect 分支 | 架构不同 |
