## 5. Rust-only 管理 API 提案

旧根文档中的 `/druid/api/*` 设计不属于 Java `druid-admin` 的迁移基线，
只能作为 Java 兼容面之外的 Rust 扩展。扩展路由不得替代 `/druid/*`、
`/druid/service.json`、静态资源、排序分页和 result code 等 Java 结果语义。

当前源码已存在真实 Axum Router、handler、DTO 和序列化实现；以下扩展仍与
Java compatibility route 分开记账。旧提案中的 UUID/fetchedAt 新信封未采用，
因为它会改变已公开的 Java `ResultCode`/`Content` 语义；需要该信封时应另开
版本化 API，而不是混入本次迁移。

| ID | Rust 扩展合同 | 当前证据 | 状态 |
| :--- | :--- | :--- | :--- |
| ADM-EXT-001 | `GET /druid/api/datasources` | 真实 handler | IMPLEMENTED_UNVERIFIED |
| ADM-EXT-002 | `GET /druid/api/datasources/:id` | 真实 handler；保留 id path | IMPLEMENTED_UNVERIFIED |
| ADM-EXT-003 | `GET /druid/api/sql/top` | 真实 handler；使用 Java 排序分页参数 | IMPLEMENTED_UNVERIFIED |
| ADM-EXT-004 | `GET /druid/api/sql/slow` | 真实 handler；当前与 list 同聚合语义 | PARTIAL |
| ADM-EXT-005 | `GET /druid/api/wall` | 真实 handler | IMPLEMENTED_UNVERIFIED |
| ADM-EXT-006 | `GET /druid/api/active` | 真实 handler，要求 serviceId/id | IMPLEMENTED_UNVERIFIED |
| ADM-EXT-007 | `GET /metrics` Prometheus 文本 | tokio-metrics TaskMonitor | IMPLEMENTED_UNVERIFIED |

以下统一信封保留为旧文档中的历史提案，当前实现没有冻结或公开该合同：

```json
{
  "id": "uuid-v4",
  "kind": "DataSourceInfo | SqlStat | WallViolation | ConnectionInfo",
  "fetchedAt": "RFC-3339 UTC",
  "payload": {}
}
```

若未来通过独立版本化 API 采用该提案，错误信封必须包含 `id`、
`kind = "Error"`、`fetchedAt` 以及结构化
`error.code`、`error.message`、`error.source`。不得把内部错误栈、数据库凭据、
原始参数或其他 PII 暴露到管理 API。

| DTO | 必需语义 |
| :--- | :--- |
| `DataSourceInfo` | 名称、驱动、max/open/active/idle/wait 等池状态、切换版本与时间 |
| `SqlStat` | SQL 或脱敏表示、指纹、执行/错误次数、总耗时、最大耗时、分位数 |
| `WallViolation` | 脱敏 SQL、指纹、命中规则、数据源和发生时间 |
| `ConnectionInfo` | 非敏感连接 ID、数据源、状态、持有时长、使用次数和最近 SQL 指纹 |

标签规则：`data_source` 使用 kebab-case，`wall_rule` 使用 snake_case，
`sql_fingerprint` 使用稳定的 64 位十六进制表示。上述命名属于 Rust 扩展，
Java 兼容 DTO 仍以 Java fixture 的字段名、nullability 和数值范围为准。

## 6. 验收

Java admin 没有完善的现成测试套件，因此需建立 oracle：

1. 直接调用 Java `MonitorStatService` 生成固定 fixture；
2. Rust 对同一节点响应执行聚合；
3. 比较 JSON、排序、分页、错误和空值；
4. 用 Axum/Tower 真实请求测试路由；
5. 用本地 HTTP fixture 测 timeout、非 2xx、坏 JSON、部分节点失败。

当前模块级 `cargo check --all-targets` 已通过，但仍不能标记任何 `ADM-*`
为 `PASS`。按批量迁移顺序，Java oracle、Tower 真实请求、本地 HTTP 故障
fixture 与覆盖率统一留在三模块迁移完成后的验证阶段。
