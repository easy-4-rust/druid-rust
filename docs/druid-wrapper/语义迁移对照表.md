## 4. SQLite 真实证据

| 测试 | 真实路径 | 结果 |
| :--- | :--- | :--- |
| `sqlite_wrapper_semantics_test` direct | facade → SQLx → SQLite，含 warning/clear 与关闭状态 | 5/5 |
| 同测试 bb8 | facade → bb8 lease → SQLx → SQLite | 通过 |
| 同测试 deadpool | facade → deadpool Object → SQLx → SQLite | 通过 |
| `sqlx_connection_adapter_test` | SQLx typed/prepared/tx/savepoint，以及 Prepared 资源 setter/query/update/generic/batch/Filter | 6/6 |
| `sqlx_bb8_pool_test` | bb8 return/timeout/broken | 5/5 |
| `sqlx_deadpool_pool_test` | deadpool return/timeout/closed | 5/5 |
| `rbdc_connection_adapter_test` | RBDC 公开错误消息/类型/warning/丢弃边界 | 6/6；错误映射为 `SqlException` |
| `rbdc_connection_adapter_test` Prepared 资源 | pooled facade → RBDC Adapter → 严格公开 SPI fixture | 1/1；setter 时点、query/update、两批值与顺序通过 |
| 同测试 LOB/SQLXML/Object | pooled facade → RBDC Prepared → 公共物化器 → 严格 SPI | 1/1；12 参数精确值及 7 类 setter 错误/unsupported 时序通过 |
| 隔离 `rbdc-sqlite` 预言机 | `rbdc::Connection` → `rbdc-sqlite 4.9.5` → SQLite 内存库 | BLOB/TEXT/URL/RowId 参数化插入及查询回读通过 |

严格结论：SQLx/bb8/deadpool 的 SQLite 主链有真实证据；SQLx Prepared 资源
setter 与 generic/batch 只在 SQLite 后端闭合，不能外推到 Any/PostgreSQL/MySQL。
SQLx/RBDC 的公开
Connection SPI 均没有 JDBC warning 读取入口，因此 Adapter 只在连接存活时返回
`None` 并允许 clear，不伪造 warning。RBDC Adapter 严格 SPI 与真实 SQLite
driver 值合同已分别通过，但因两套 `libsqlite3-sys` 的 `links=sqlite3` 冲突，
尚无同一 workspace/进程的组合端到端。RBDC 4.9 公开错误仅为字符串，因此
vendor code/SQLState 不可从当前接口提取。Java
wrapper 13 对象的配置兼容也未闭合，所以模块保持 `PARTIAL`。
