# Druid 1.2.28 → druid-rust 对象级迁移对照表

> 本表是对象迁移账本。它回答“Java 对象的职责由哪些 Rust 对象承载”，不以文件数量相等为目标，也不允许用“Rust 没有 Java API”删除功能。完整行为见[语义迁移对照表](./3、语义迁移对照表.md)，连接层边界见[连接抽象与驱动适配架构](./5、连接抽象与驱动适配架构.md)。

模块归属固定为 `druid`、`druid-admin`、`druid-wrapper` 三个。表中的
`druid/src/core/...`、`druid-wrapper/src/sqlx/...` 等均为当前物理源码路径。

## 1. 基线与状态

Druid core 主源码共 1,644 个 Java 文件，分布如下：

| 域 | 文件数 | 域 | 文件数 |
| :--- | ---: | :--- | ---: |
| `sql` | 1,268 | `support` | 105 |
| `pool` | 72 | `wall` | 46 |
| `proxy` | 36 | `util` | 35 |
| `filter` | 29 | `stat` | 24 |
| `mock` | 22 | core 根对象 | 7 |

全仓生产 Java 文件为 1,719 个，还包括 starter、wrapper、admin 和 demo。正式执行时，对象账本必须扩展到 1,719/1,719；本文先冻结核心对象、对象族及非 core 模块的迁移落点。

| 状态 | 含义 |
| :--- | :--- |
| `DONE` | 当前源码存在，关键语义已有 Java 差分证据 |
| `PARTIAL` | 当前源码存在，但字段、路径或行为不完整 |
| `BROKEN` | 当前源码存在，但已确认关键路径错误 |
| `MISSING` | 尚无可运行落点 |
| `RENAME` | 有近似实现，但 canonical 对象/文件名不一致 |
| `ADAPTER` | 计划由外部 crate/协议承载，仍需 Druid 契约验收 |
| `RUST_ONLY` | Rust 内部新增对象，必须注明承载的 Java 语义 |

目前没有对象可以仅凭同名或单元测试数量标记 `DONE`。以下状态来自 CodeGraph、源码扫描和 `cargo +stable test --workspace`，计划文件一律不算实现。

## 2. 映射规则

1. `DIRECT` 对象保留 Java 语义名称：类型 PascalCase、文件 snake_case。
2. `MERGE` 必须逐个列出所有源对象；不能写“其他 30 个 util”。
3. `SPLIT` 必须指定 canonical facade，避免调用者理解内部拼装。
4. `ADAPTER/PROTOCOL` 必须列出外部类型、兼容层和验收契约，不能只写 crate 名。
5. 一个 `.rs` 文件只定义一个迁移对象；Builder/内部类型可与主对象同文件。
6. `mod.rs/lib.rs` 只声明和重导出，不堆放迁移对象。

### 2.1 Druid 对象与平台依赖分账

`java.sql.*`、`javax.sql.*` 是 Java/JDBC 平台标准，不是 Druid 仓库生产对象。它们必须有 Rust 能力映射，但不计入 1,719 个 Druid 对象的迁移分母。

| Java 平台对象 | Rust 能力落点 | 分类 | 边界 |
| :--- | :--- | :--- | :--- |
| `java.sql.Connection` | `PhysicalConnection` + typed request/result | PLATFORM_ADAPTER | druid-rust 内部最小 SPI，不直接对应用公开 |
| `java.sql.Driver` | `PhysicalConnectionFactory` + driver registry | PLATFORM_ADAPTER | 仅创建 raw physical connection，不管理池租约 |
| `javax.sql.DataSource` | `DruidDataSource` + `ConnectionProvider` | PLATFORM_ADAPTER | facade 对外；Provider 决定 native/bridge 来源 |
| `java.sql.Statement` / `PreparedStatement` / `ResultSet` | `PhysicalPreparedStatement`、执行请求/结果和后续借用行流 | PLATFORM_ADAPTER | PreparedStatement 物理句柄已接入 SQLx/RBDC；参数 setter、流关闭和完整 ResultSet 仍待迁移 |
| `java.sql.CallableStatement` | `PhysicalCallableStatement` + `CallableInputParameter` + `CallableOutputValue` + `CallableParameter` + `CallableOutParameter` | PLATFORM_ADAPTER | 输入 setter 身份及 sqlType/typeName/scale/Calendar/LOB/Reader 精确长度重载必须无损；SQLx/RBDC 当前无统一标准，必须显式 unsupported，不得用普通 SQL 句柄伪装 |
| `java.sql.Blob` | `JdbcBlob` + `PhysicalBlob` | PLATFORM_ADAPTER | 完整 11 方法资源 SPI；对象身份比较，禁止静默物化为 Vec |
| `java.sql.Clob` / `NClob` | `JdbcClob`/`PhysicalClob` + `JdbcNClob`/`PhysicalNClob` | PLATFORM_ADAPTER | Clob 完整 13 方法；NClob 保留继承类型身份；禁止静默物化为 Rust String |
| `java.lang.String` | `JavaString` | PLATFORM_ADAPTER | UTF-16 code unit 值对象，可无损表达未配对 surrogate |
| `java.io.Reader/Writer` | `JdbcReader/JdbcWriter` | PLATFORM_ADAPTER | Clone 共享游标/关闭状态；池化层不得提前消费 |
| `java.io.InputStream/OutputStream` | `JdbcInputStream/JdbcOutputStream` | PLATFORM_ADAPTER | Clone 共享游标与关闭状态；池化层不得提前消费 |
| `java.util.Calendar` | `CallableCalendar` + `CallableCalendarArgument` | PLATFORM_ADAPTER | 保留时区标识与 Calendar 重载/null 身份，不缩成瞬时 offset |
| `java.math.BigDecimal`、`java.sql.Date/Time/Timestamp` | `bigdecimal` + `chrono` 强类型 | PLATFORM_ADAPTER | 保留任意精度/scale、日期时间类型和 Timestamp 纳秒 |
| Toasty `Driver` / `Connection` | `ToastyConnectionFactory` / `ToastyConnectionAdapter` | RUST_ECOSYSTEM | `druid` 内置标准实现；每次创建 raw connection，不使用 Toasty pool |
| `sqlx::Connection` | `SqlxConnectionAdapter` | RUST_ECOSYSTEM | direct adapter，不携带 SQLx pool |
| `rbdc::db::Connection` | `RbdcConnectionAdapter` | RUST_ECOSYSTEM | direct adapter |
| bb8/deadpool lease | `SqlxBb8Pool` / `SqlxDeadpoolPool` + `PhysicalConnectionLease` | RUST_ECOSYSTEM | bridge 直接实现 core `Pool`，不进入 native idle queue |

Rust 标准库没有与 JDBC `java.sql.Connection` 对等的统一数据库连接标准。SQLx、RBDC、Diesel 驱动等属于生态 crate，抽象层级和能力集合并不相同；因此这里迁移的是 JDBC 作为 Druid 底层平台所提供的**能力契约**，由内部 `PhysicalConnection` 统一，再由各驱动 Adapter 实现，而不是虚构一个不存在的 Rust 标准库类型。

## 14. 对象关闭条件

一个对象只有同时满足以下条件才可标 `DONE`：

- Java FQCN、源提交、Rust 类型和文件均已登记；
- 映射形态及必要 ADR 已批准；
- 字段默认值、公开方法、错误、副作用和并发语义有契约；
- Java fixture 与 Rust 测试差分通过；
- 中文 doc 注释注明 Java 来源；
- 名称检查、无 stub 检查、CodeGraph 调用链检查通过；
- 若由 enum 承载，源对象对应的 variant 不与其他对象混账。
