## 标准常量与授权异常分类迁移（2026-10-08）

JDBC编号的标准模块入口为 `druid_rdbc::types::types`，例如 `types::INTEGER`；原有 `druid_rdbc::types::Types::INTEGER` 以及 `druid::sql::Types::INTEGER` 仍指向同一编号。全部39个常量已按固定Java源码与实际Java反射结果核对。

授权异常的规范枚举项为 `InvalidAuthorizationSpec`。旧variant专用导入在当前产物上实际返回E0432：

```rust
pub use druid_rdbc::error::SqlExceptionKind::InvalidAuthorization;
```

改用规范枚举项导入：

```rust
pub use druid_rdbc::error::SqlExceptionKind::InvalidAuthorizationSpec;
```

限定值访问 `SqlExceptionKind::InvalidAuthorization` 保留为同值关联常量，Debug仍展示历史名称；这不保留上述旧variant专用导入。该公开形态变化须进入最终breaking allowlist和真实SemVer验证，目前尚未完成发布认证。

具体标准SQL异常先按记录的标准类名确定kind，随后使用recoverable标志和SQLState作为fallback。12个具体标准类的空SQLState与冲突SQLState已取得24条Java/Rust同输入一致证据；不能扩大为任意vendor子类继承认证。

[本轮实现与验证边界](../verification/rdbc-first/task8-constant-exception-contract-recovery-2026-10-08.md)。

| --- | --- |
| `RdbcArray::state`、`RdbcBlob::state`、`RdbcClob::state`、`RdbcNClob::state`、`RdbcSqlXml::state` | 使用各句柄的 `is_freed()` 判断已确认释放；`Releasing` 等 owner 中间状态不再作为 RDBC 公共枚举暴露。取消或失败后的 `free()` 仍须按原错误/重试合同处理，不能把 `!is_freed()` 等同于可读。 |
| `RdbcRef::state` | Java `Ref` 没有 `free`。当前句柄直接委托标准 `Ref` 的读写操作并保留克隆身份；调用方应处理操作返回的错误和父连接生命周期，不再查询凭空附加的释放状态。 |
| `RdbcOpaqueObject::physical` | 使用 `value()` 得到 `dyn OpaqueObjectValue`，或 `downcast_ref<T>()` 作受控类型访问；旧 `PhysicalRdbcOpaqueObject` 实现须迁入标准值接口。 |
| `RdbcXmlSource::physical`、`RdbcXmlResult::physical` | 分别使用 `value()` 得到 `dyn XmlSource` / `dyn XmlResult`；旧 `PhysicalXmlSource` / `PhysicalXmlResult` 实现须迁入标准扩展接口。 |

这九项是预发布 API 迁移，不代表 Task7 的资源能力、取消监管和实库验收已关闭。`resource_standard_contract_test` 当前 31/31 通过，全工作区默认目标通过；外部下游仍需按上表迁移并单独编译验证。

## Wrapper 具体语句与元数据类型迁移（pre-release）

`druid-wrapper/struct_missing` 的 11 条路径是 9 个已退休的具体类型；RBDC 与 Toasty 的预编译语句各有模块路径和重导出路径，因此各计两条。旧具体类型不能用类型别名恢复：新实现共享同一标准执行器，并由连接返回 trait 对象。

| 旧类型 | 当前获取方式 |
| --- | --- |
| `RbdcPreparedStatement`、`LibSqlPreparedStatement`、`HttpSqlPreparedStatement`、`ToastyPreparedStatement`、`DuckDbPreparedStatement`、`JdbcAgentPreparedStatement` | 在对应未池化连接上调用 `Connection::prepare_statement`，接收 `Box<dyn druid_rdbc::statement::PreparedStatement>`；各后端委托 `StandardAdapterPreparedStatement`。 |
| `LibSqlDatabaseMetaData`、`HttpSqlDatabaseMetaData`、`DuckDbDatabaseMetaData` | 调用 `Connection::database_meta_data`，接收 `Box<dyn druid_rdbc::metadata::DatabaseMetaData>`；各后端委托 `StandardAdapterDatabaseMetaData`。 |

调用方若依赖旧具体类型的构造器或字段，须改为标准连接的能力调用。当前 Wrapper 生产源码已无这些旧类型引用；预编译矩阵、适配器边界和 Toasty 原生元数据测试分别通过 15/15、4/4、9/9。这是预发布公开路径迁移，仍需外部消费者与完整实库矩阵验收，不据此关闭 P04/P05/P07。

## Wrapper 自动 trait 迁移（pre-release）

`druid-wrapper/auto_trait_impl_removed` 的 23 条报告涵盖七种工厂或外部池管理器（部分路径重复）失去 `UnwindSafe`、`RefUnwindSafe`，以及 `JdbcAgentConnection` 失去 `Sync`、`UnwindSafe`、`RefUnwindSafe`。新工厂持有可共享的驱动、连接器或运行轨迹状态；JDBC Agent 连接独占可变传输对象，标准 `Connection` 合同仅要求 `Send`。这些自动 trait 不属于可安全强制恢复的连接并发或 panic 恢复承诺。

下游若以这些具体类型作为 `catch_unwind` 边界，应在自身已验证状态恢复语义后显式包装该边界；若共享 `JdbcAgentConnection`，应通过标准连接所有权与同步机制串行访问，不能假定连接对象自身为 `Sync`。本项只批准预发布 API 迁移，不证明 panic 后连接可继续使用，也不关闭并发、故障注入或实库验收。
