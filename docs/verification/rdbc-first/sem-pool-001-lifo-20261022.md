## 1. 差异

| 侧 | 行为 | 证据 |
|---|---|---|
| Java | `putLast` 追加到数组尾部，`pollLast` 从尾部取 → **后归还者先复用（LIFO）** | `DruidDataSource.java:2225` `pollLast`；`putLast` 追加 |
| Rust（修复前） | `push_back` + `pop_front` → FIFO | `crates/druid/src/pool/druid_pool.rs` 借用处 |
| Rust（修复后） | `push_back` + `pop_back` → LIFO | 同上，附 Java 来源注释 |

影响面：热连接复用率、`testWhileIdle` 的实际校验对象、`shrink` 的驱逐次序、`keepAlive` 重新入队后的借出顺序。

## 2. 变更

1. `crates/druid/src/pool/druid_pool.rs`：`idle.pop_front()` → `idle.pop_back()`，并补充 Java `pollLast` 来源注释。
2. `crates/druid/src/pool/pool_inner.rs`：在 `push_back` 处补充 `putLast`/LIFO 语义注释（行为不变）。
3. 新增 `crates/druid/tests/pool_idle_reuse_order_test.rs`：用可观测连接序号断言“后归还者先借出”。
4. 修正 `crates/druid/tests/task6_maintenance_semantics_test_parity.rs`：
   - 原断言方向按 FIFO 编写；
   - 原写法 `pool.get().await.unwrap().id()` 的临时值在语句结束即归还，导致两次借到同一连接（`10002/10002`）；
   - 改为同时持有两个租约，并按 Java LIFO 断言 `first_id > second_id`。

## 4. 仍未闭合

- idle 时间字段（`last_active`/`last_exec`/`last_keep`）与借用顺序的交互未逐项差分；
- `shrink` 驱逐顺序与 LIFO 的交互只有队列顺序断言，缺 Java 对照用例；
- fair/unfair 唤醒顺序属平台差异（`parking_lot` 非公平 `Mutex` 对应 Java `useUnfairLock` 默认），不随本次改动闭合。

因此 `SEM-POOL-001` 仍为 `PARTIAL`，本次只关闭“借用顺序”子项。
