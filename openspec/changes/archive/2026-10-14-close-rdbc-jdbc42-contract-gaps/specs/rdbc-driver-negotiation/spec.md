# JDBC 驱动协商

## Purpose

规定多个驱动共存时的选择顺序、连接尝试和异常保真行为，使应用通过统一注册表及兼容 DriverManager 获得一致结果，避免首个失败驱动阻断后续可用连接。

## ADDED Requirements

### Requirement: DN-01 查找驱动与建立连接使用不同协商规则

系统 SHALL 对驱动查找按注册顺序查询 URL 接受能力并返回首个接受者；建立连接 SHALL 按注册顺序调用连接协商，不以前置 URL 接受判断代替驱动的连接结果。

#### Scenario: 查找不创建连接
- **WHEN** 调用方查找某 URL 的驱动且第二个驱动首先声明接受
- **THEN** 返回第二个驱动，并且所有驱动的连接入口调用次数为零

#### Scenario: 连接返回空结果后继续
- **WHEN** 首个驱动的连接结果为空、第二个返回连接
- **THEN** 返回第二个连接，保持尝试顺序，且不调用无关的驱动名称或 URL 接受入口

### Requirement: DN-02 后续成功优先于前序 SQL 异常

系统 SHALL 在驱动连接返回 SQL 异常后继续尝试后续注册驱动；后续成功则返回其连接，全部没有成功则返回首次异常，并保留其类型、SQLState、vendor code、cause 和 next 链。

#### Scenario: 首个异常后成功
- **WHEN** 第一个驱动返回 SQL 异常而第二个成功
- **THEN** 返回成功连接，第三个驱动不再被调用

#### Scenario: 全部失败保留首次异常
- **WHEN** 驱动依次返回异常 A、空结果、异常 B
- **THEN** 调用方取得异常 A 的完整载荷，不能被 B、字符串拼接或通用错误覆盖

#### Scenario: 没有驱动可连接
- **WHEN** 所有注册驱动都返回空结果或注册表为空
- **THEN** 标准注册表返回无匹配结果，JDBC 兼容入口返回 SQLState 为 08001 的无合适驱动错误

### Requirement: DN-03 协商快照与调用边界

系统 SHALL 在一次连接尝试中使用稳定的注册顺序快照，在注册表锁之外调用第三方驱动；整体登录超时或调用方取消 SHALL 终止本次协商，不再启动后续驱动，敏感凭据不得写入诊断日志。

#### Scenario: 协商期间发生注册变更
- **WHEN** 某驱动连接回调期间添加或移除注册项
- **THEN** 当前尝试继续使用其开始时的快照，后续新尝试看到新注册状态，且无重入死锁

#### Scenario: 整体期限到期
- **WHEN** 连接协商超过调用方设置的登录期限
- **THEN** 返回超时类别错误，不继续尝试下一个驱动，并按驱动 owner 合同清理已发起的操作
