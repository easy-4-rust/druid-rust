## 当前执行卡：4.5–4.7 取消控制

本执行卡只负责 SC-01–05 的剩余验收，不提前开始池化事件、XA 或其他批次。4.1–4.4 已由 [取消合同证据](evidence/cancellation-contract.md) 和 [SQLx 取消能力矩阵](evidence/sqlx-cancellation-capability-matrix.md) 关闭，不重复实现。完成 4.5–4.7 后报告结果并停止，测试失败只在代码或测试有新变化时重跑。

验收时逐层区分四类证据，不能相互替代：

1. **标准合同**：不支持能力精确返回 0A000；支持能力可在 Statement 执行 Future 挂起时由独立任务调用。
2. **Druid 代理**：普通、PreparedStatement、CallableStatement 均转发到原语句的取消控制；关闭逻辑句柄、归还租约或复用缓存语句后，旧句柄不能触达新租约。
3. **适配器执行路径**：分别检查流式游标、缓冲查询和 `execute` 等入口。能力只接入部分路径时，未接入路径必须拒绝声明支持，并在能力矩阵中精确列出。
4. **真实后端**：至少运行一个由准备阶段选定的真实后端长查询；记录请求开始、取消结果、服务端执行终态、后续查询结果及连接复用/丢弃决定。小型即时 `SELECT`、mock、取消 Future 本身和本地 cursor drop 均不能替代该证据。环境不可用则记录 `NOT_RUN`，本批不通过。

最低回归范围是 `druid-rdbc` 取消合同、`druid` 普通/预编译/调用语句代理生命周期，以及选定 wrapper 的真实后端取消路径。每次运行记下精确命令、feature、后端版本、退出码和对应源码哈希。4.3 已关闭；满足 4.4–4.5 与上述四层证据后结束取消批；有一层不满足就只修复该缺口或报告具体阻断，不顺延开始第 5 批。

### 下一步执行顺序与明确停止点

本执行批的目标是关闭“SQLx 取消控制与 Druid 租约的端到端合同”，不扩展成所有后端都支持取消，也不把 `NOT_RUN` 记为通过。每个阶段只运行列出的目标测试和直接受影响回归；出现未解决的验收失败时停止在该阶段，报告具体阻断。

1. **核对真实 SQLite 正向路径（4.5）**：SQLx SQLite 已固定为取消正向验收后端；复核长查询用例是否记录数据库 VM 执行终态、取消后的查询结果及连接复用/丢弃决定，并补齐缺项。当前 PostgreSQL/MySQL 的实库 `0A000` 只证明负向能力。SQLite 正向证据满足固定验收后端的所有记录要求时可用于关闭 4.5，不额外要求 PostgreSQL 正向取消；若 SQLite 缺少执行终态证据，保持 4.5 未完成并报告具体缺项，不通过降低断言或改用即时查询关闭任务。
3. **最后同步矩阵、用户文档和证据（4.6、4.7）**：能力表、标准/代理示例、任务证据和实现必须一致；重新运行本批目标测试及最低回归，更新哈希。所有验收项通过后停止并报告，不自动开始 5.1。

**本批完成判定：**4.5–4.7 全部有实际证据，且后端正向和负向路径、连接处置、旧租约隔离均可复核，才把相应任务勾选并将批次状态改为完成。仅有模拟测试、类型/符号存在、编译成功、Future 结束或实库 `0A000` 均不满足该判定。
