# Spec Delta

## Purpose

以完整来源分母和可追溯证据判定迁移是否完成，使实现、测试、真实宿主和发布结论不再被同名类型、历史绿灯或局部覆盖率混淆。

## ADDED Requirements

### Requirement: 当前源码必须先形成可信基线

验收 SHALL 使用明确的 Java/Rust 提交和工作区快照，默认及全部 feature 的编译、测试和严格静态检查必须通过；历史通过记录不得替代当前结果。

#### Scenario: 当前源码存在编译或严格检查错误
- **WHEN** 当前工作区的生产代码缺少正式依赖、存在未使用警告或旧测试与 Java 合同冲突
- **THEN** 基线保持未通过，修复后重新执行受影响及下游门禁，不进入完成评审

### Requirement: 全部来源测试具有可追踪处置

每个来源测试及每个具体参数化、动态或重复用例 SHALL 保留独立身份、输入、断言、错误预期、状态、副作用和清理，并具有可定位的目标实现与差分结果。

#### Scenario: 存在未映射、阻塞或未执行用例
- **WHEN** 任一来源用例为 MISSING、BLOCKED、NOT_APPLICABLE 或 NOT_RUN
- **THEN** 迁移完成门禁保持失败，不能用其他 Rust 测试通过抵消

### Requirement: 测试资产逐字节一致

每个来源 fixture、脚本、语料、golden 文件和数据资源 SHALL 记录源路径、目标路径与 SHA-256；派生文件 SHALL 与不可变原件分开保存。

#### Scenario: 资源内容或哈希不一致
- **WHEN** 任一来源资产缺失、被原地修改或目标哈希不同
- **THEN** 对应来源用例不得通过 SOURCE_PARITY，修复资产后重新执行其差分

### Requirement: JDBC 方法按证据层分别验收

方法清单 SHALL 分别记录声明、合同、适配器、逻辑代理、真实数据库与负能力证据；未评估项 SHALL 保持未评估，不能由对象存在推导行为完成。

#### Scenario: 只有声明或本地合同证据
- **WHEN** 方法只有 Rust 类型或本地测试，尚无适配器和真实数据库结果
- **THEN** 只能声明对应层次通过，真实数据库与完整能力仍为未验证

### Requirement: 差分结果以逐用例可观察行为为准

Java 与 Rust SHALL 在固定基线上执行相同用例并比较成功值、错误类别、顺序、状态、副作用及清理；仅独立绿色套件、同名测试或总数相近不得视为差分通过。

#### Scenario: 任一用例输出不同或比较设施失败
- **WHEN** 出现 MISMATCH、harness failure 或 not-run case
- **THEN** 差分门禁失败并保留原始输出，禁止通过宽泛归一化或重拍快照隐藏差异

### Requirement: 覆盖率按明确范围报告

覆盖率 SHALL 记录生产文件、排除项、feature、目标、测试类型和工具语义，并分别报告行、函数、区域或分支结果；覆盖率 SHALL 仅作为风险信号。

#### Scenario: 只有局部 crate 或 scoped 覆盖率
- **WHEN** 仅执行部分 crate、部分测试或部分 feature 的插桩
- **THEN** 报告明确标注 scoped，不得宣称全仓覆盖率或整仓迁移门禁通过

### Requirement: 最终验收证据决定发布状态

最终报告 SHALL 汇总源码、测试、差分、真实宿主、性能、安全、API、覆盖率和回滚证据；任一必需项缺失或失败时，项目保持 NOT_READY 且不得发布。

#### Scenario: 仍有真实数据库或回滚证据缺口
- **WHEN** 实现与单元测试通过但真实数据库、崩溃恢复或回滚演练未执行
- **THEN** 不得生成 RELEASE_READY 结论，报告列出具体未执行项及原因
